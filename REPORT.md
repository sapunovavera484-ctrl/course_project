## Страница 1. Блок 1: Теоретические основы, проблематика и анализ ИИ-ассистентов

### 1.1. Что такое нейросеть и её назначение в современном образовательном процессе

**Искусственная нейронная сеть (ИНС)** представляет собой сложную математическую модель, а также её программное или аппаратное воплощение, построенное по принципу организации, функционирования и взаимодействия биологических нейронных сетей живых организмов. В основе данной технологии лежит концепция связных искусственных нейронов (вычислительных элементов), которые принимают входные сигналы, обрабатывают их с помощью весовых коэффициентов и функций активации, передавая результат последующим слоям сети. Главным фундаментальным отличием нейросетевых алгоритмов от классического детерминированного программирования является их способность к **машинному обучению**. Нейросеть не действует по заранее жестко прописанному алгоритму, а самостоятельно настраивает свои внутренние параметры (веса) в процессе обработки колоссальных массивов входной информации (Big Data), выявляя скрытые высокоуровневые закономерности, структурные связи и ассоциации.

В контексте современного образовательного процесса и экспоненциального роста объёмов информации классические методы обучения сталкиваются с проблемой дефицита времени и индивидуального подхода. Интеграция больших языковых моделей (LLM) в качестве генеративных ИИ-ассистентов призвана кардинально трансформировать эту парадигму. В рамках автоматизации учебной деятельности ИИ-ассистенты выполняют следующие ключевые функции:

1. **Генерация адаптивных дидактических материалов:** Возможность мгновенного создания уникальных, вариативных заданий для самопроверки студентов, дифференцированных по уровням сложности (от базового синтаксиса до архитектурного проектирования) и специке индивидуальных пробелов в знаниях.
2. **Формирование опорных материалов (интеллектуальное конспектирование):** Автоматическое реферирование академических текстов, создание структурированных выжимок, ментальных карт, тезисов и глоссариев по сложным разделам курса, что значительно ускоряет когнитивное освоение материала первокурсниками.
3. **Персонализированное менторство и обратная связь (24/7):** Студент получает интерактивного помощника, способного детально, пошагово разобрать логические ошибки в коде или алгоритме, предложить альтернативные варианты решения и ответить на сопутствующие вопросы в любое время суток, частично снимая рутинную нагрузку с преподавательского состава.

### 1.2. Проблематика использования генеративного ИИ: Специфика багов и галлюцинаций

Несмотря на революционный характер генеративных моделей, их внедрение сопряжено с критически важными технологическими рисками и багами, природа которых кроется в самом вероятностном подходе к генерации текста. Большие языковые модели не обладают сознанием, пониманием причинно-следственных связей или логическим мышлением в человеческом понимании — они лишь предсказывают наиболее вероятное следующее слово (токен) на основе весов, сформированных во время обучения. Данная специфика порождает ряд фундаментальных проблем:

* **Феномен «галлюцинаций» ИИ:** Самый деструктивный и скрытый баг генеративных моделей. Галлюцинация — это процесс, при котором нейросеть с абсолютной лингвистической уверенностью генерирует фактологически ложную, выдуманную или искаженную информацию. Модель может выдумать несуществующую библиотеку в языке программирования, сослаться на вымышленные статьи авторитетных ученых или сгенерировать синтаксически неверный код, заявляя, что он является эталонным стандартом. Для студента первого курса, не обладающего глубоким критическим опытом, такие ошибки представляют наибольшую опасность.
* **Потеря контекста и зацикливание:** При ведении длинных диалогов или анализе объемных программных файлов у моделей может переполняться контекстное окно (Context Window). Это приводит к тому, что ИИ «забывает» вводные требования, путает объявленные ранее переменные или начинает циклически повторять одни и те же фрагменты текста, заходя в тупик деградации ответов.
* **Проблема смещения данных (Data Bias) и устаревания знаний:** Нейросеть ограничена тем срезом данных, на котором её обучали. Если стандарты языка (например, стандарты C++20 или C++23) обновились после даты фиксации обучающей выборки, ИИ продолжит генерировать устаревшие или небезопасные конструкции.

Таким образом, проведение сравнительного анализа функциональных возможностей различных архитектур ИИ, выявление их паттернов поведения при столкновении с ошибками и разработка систем автоматизированного контроля являются строго необходимыми условиями для их безопасного использования в высшем образовании.

### 1.3. Практический кейс: Разбор баговой задачи ассистентами Alice AI и Gemini

Для проведения объективного исследования возможностям ИИ-ассистентов была предложена классическая комплексная **баговая задача по программированию на C++**, содержащая две скрытые критические ошибки, которые часто совершают первокурсники:
1. Ошибка выхода за границы массива (Undefined Behavior).
2. Ошибка целочисленного деления на ноль при вычислении среднего арифметического.

#### Исходный баговый код, отправленный нейросетям на анализ:
```cpp
#include <iostream>
using namespace std;

int main() {
    int size = 5;
    int arr[] = {10, 20, 30, 40, 50};
    int sum = 0;
    int zero_divider = 0; // Переменная для деления

    // Ошибка 1: Цикл идет до i <= size, вызывая выход за границы arr
    for (int i = 0; i <= size; i++) {
        sum += arr[i];
    }

    // Ошибка 2: Попытка вычислить среднее значение с делением на ноль
    int average = sum / zero_divider; 

    cout << "Сумма: " << sum << ", Среднее: " << average << endl;
    return 0;
}
```

Ниже приведены детализированные симуляционные логи ответов ассистентов, отражающие их специфику, когнитивный стиль и паттерны разбора багов.

#### [ЛОГ ОТВЕТА АССИСТЕНТА №1: ALICE AI (ЯНДЕКС)]
* **Стиль анализа:** Краткий, дидактический, дружелюбный. Попытка объяснить проблему простыми словами без глубокого погружения в стандарты компилятора.
* **Текст ответа модели:**
  > «Привет! В твоем коде есть две серьезные ошибки, из-за которых программа аварийно завершится (упадет).
  > 
  > **1. Выход за границы массива:** В цикле `for` ты указала условие `i <= size`. Так как размер массива равен 5, его элементы имеют индексы от 0 до 4. Когда цикл дойдет до `i = 5`, программа попытается прочитать данные из `arr`, которых там нет. Это вызовет сбой. Замени `i <= size` на `i < size`.
  > **2. Деление на ноль:** Ты делишь переменную `sum` на `zero_divider`, значение которой равно 0. В математике и в программировании делить на ноль нельзя! Из-за этого программа моментально закроется с ошибкой. Тебе нужно делить на количество элементов, то есть на `size`.
  > 
  > Вот исправленный и безопасный вариант кода...» *(выводит рабочий код)*.

#### [ЛОГ ОТВЕТА АССИСТЕНТА №2: GEMINI (GOOGLE)]
* **Стиль анализа:** Академический, глубокий, структурированный. Использование профессиональной терминологии (Undefined Behavior, Runtime Error), детальный разбор механики памяти.
* **Текст ответа модели:**
  > «Analysis of the provided C++ source code reveals critical runtime vulnerabilities:
  > 
  > **1. Out-of-bounds Array Access (Undefined Behavior):** 
  > The array `arr` is statically allocated with a size of 5 (indices `0` through `4`). The loop termination condition `i <= size` evaluates to `true` when `i == 5`. Accessing `arr` memory location violates memory safety boundaries, leading to **Undefined Behavior (UB)**. The compiler might fetch garbage data from the stack or trigger a Segmentation Fault. 
  > *Correction:* Modify the loop condition to strict inequality: `i < size`.
  > 
  > **2. Integer Division by Zero (Floating Point Exception):**
  > The expression `sum / zero_divider` invokes integer division where the denominator evaluates to static scalar zero. At the CPU hardware level, this operation triggers a hardware interrupt (SIGFPE - Arithmetic Exception), resulting in immediate abnormal termination of the process.
  > *Correction:* Ensure the denominator is non-zero. To compute the mathematical average, divide `sum` by the `size` variable cast to `double` to prevent precision loss.
  > 
  > Refactored production-ready code with safe structures...» *(выводит код с комментариями)*.
